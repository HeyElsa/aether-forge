# @aether-forge/sdk

TypeScript SDK for [Aether Forge](https://github.com/HeyElsa/aether-forge) — validators, types, and the language-agnostic planner-output parser. Conforms to the JSON schemas published at `https://schemas.aether-forge.dev/`.

**Status**: v0.1.0 (Sprint 3 of the dev-feedback retrospective). Tracks the Python framework at `^0.23.0` per `package.json:schemaCompat`.

---

## What's in v0.1.0

Three layers — all interface-only / pure functions, no runtime tick loop.

### 1. Generated types (19 schemas)

```ts
import {
  AgentSpec,
  CapabilityManifest,
  PolicyBundle,
  ScenarioPack,
  ResearchRecord,
  PromotionRecord,
  MemoryRecord,
  ScaffoldManifest,
  ArtifactEnvelope,
  ArtifactRef,
  Compatibility,
  MigrationContract,
  ActiveComparisonContract,
  AgentConfig,
  DelegatedSigner,
  PlannerOutput,
  PlannerToolUse,
  PolicyDecisionRecord,
  RuntimeStepLedgerEntry,
} from "@aether-forge/sdk";
```

The bundle at `src/schemas/generated/index.ts` is generated by `scripts/generate-schemas.ts` and committed. CI verifies it matches a fresh regeneration.

### 2. Validators (ajv-backed)

```ts
import { validateAgentSpec, assertValid, validateArtifactBundle } from "@aether-forge/sdk";

const result = validateAgentSpec(json);
if (result.ok) {
  // result.value is narrowed to AgentSpec
} else {
  console.error(result.errors);
}

// Or throw-on-invalid style:
const spec = assertValid(validateAgentSpec(json));

// Validate a full bundle:
const bundle = validateArtifactBundle({
  agentSpec: ...,
  capabilityManifest: ...,
  policyBundle: ...,
  scenarioPack: ...,
});
```

One `validate*` function per artifact / runtime / common schema. `assertValid<T>` throws `ValidationError` carrying the underlying ajv error array.

### 3. Planner output parser (language-agnostic spec)

```ts
import { parsePlannerOutput, PlannerParseError } from "@aether-forge/sdk";

try {
  const plan = parsePlannerOutput(rawLlmResponse);
  // plan matches `docs/specs/planner-output.md` shape
} catch (error) {
  if (error instanceof PlannerParseError) {
    // recovery failed — fall back to a heuristic planner
  }
}
```

Implements the spec at [`docs/specs/planner-output.md`](../docs/specs/planner-output.md): code-fence stripping, reasoning-preamble recovery, balanced-brace scan with string-literal awareness. Identical behavior to the Python reference `aether_forge.planner._extract_json`, enforced by shared fixtures under `tests/fixtures/planner-outputs/`.

### 4. Protocol interfaces (interface-only)

```ts
import type {
  Planner,
  ExecutionRouter,
  MemoryStore,
  DataSource,
  PlanningModel,
  StepProposal,
  ExecutionResult,
  RuntimeSession,
  // …signers:
  DelegatedSigner as DelegatedSignerProtocol,
  SigningIntent,
} from "@aether-forge/sdk";
```

These mirror the Python Protocols at `src/aether_forge/runtime.py`, `memory.py`, `data_layer.py`, `planner.py`. v0.1.0 is interface-only — there is no TypeScript implementation of the runtime tick loop, by design (the tick loop is the highest lockstep risk; it stays Python-side until cross-language usage data justifies a port). See the plan at `~/.claude/plans/friction-points-python-only-concurrent-lecun.md`.

## Develop

```sh
bun install
bun run typecheck             # tsc --noEmit
bun run test                  # vitest, includes cross-language conformance
bun run build                 # tsup → dist/ (esm + cjs + .d.ts)
bun run generate:schemas      # regenerate src/schemas/generated/index.ts
```

CI gates: the committed `src/schemas/generated/index.ts` MUST match `bun run generate:schemas` (any drift breaks the build), and the cross-language conformance fixtures under `../tests/fixtures/planner-outputs/` MUST pass under both the Python and TypeScript reference parsers.

## Versioning

- npm semver tracks the SDK independently from the Python `aether-forge` package on PyPI.
- `package.json:schemaCompat` declares the compatible range of `https://schemas.aether-forge.dev/` schema versions. A SDK MAY parse + validate artifacts whose `schemaVersion` falls within this range.
